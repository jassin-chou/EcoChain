## 2. Model Summary

EcoChain represents the current ecosystem as a graph:

- Nodes are species or facilities currently placed on the board.
- Edges represent ecological relationships such as predation, pollination, or facility support.
- Node features use Species2Vec embeddings plus count information when available.
- Edge features encode relation type.

The model produces two outputs:

1. `gnn_score`: a model-predicted ecosystem score used as a reference signal.
2. Recommendation logits: scores used to recommend next species.

Important runtime design decision:

The player-facing ecosystem health score is not directly the GNN score. The application now uses an explainable formula from `compute_explainable_score()` as the main displayed score. The GNN is used for recommendation and graph-based analysis support.

## 3. Architecture

The model uses:

- `GATConv` layer 1 with edge attributes.
- `GATConv` layer 2.
- `GATConv` layer 3.
- Batch normalization after each graph attention layer.
- `global_mean_pool` and `global_max_pool`.
- Concatenated graph representation.
- A score head for graph-level score regression.
- A recommendation head for species recommendation logits.

The pooling design is important because EcoChain is a graph-level task. The model needs to represent the entire ecosystem, not only individual species.

| Pooling layer | Role in EcoChain |
|---|---|
| `global_mean_pool` | Captures average ecosystem state and overall species composition |
| `global_max_pool` | Preserves strong signals such as key predator, pollinator, aquatic species, or facility presence |

## 4. Intended Use

Appropriate uses:

- Recommend species that may fit the player's current ecosystem.
- Support the GNN analysis panel in the EcoChain game.
- Demonstrate graph ML in an educational ecological simulation.
- Compare graph-based recommendation with rule-based and Jaccard baselines.

Out-of-scope uses:

- Real ecological risk assessment.
- Conservation planning or policy decisions.
- Scientific food-web prediction.
- Fully automated grading of real ecosystems.

## 6. Training Data

The model is trained on graph-structured game states created from:

- Real food-web subsets in `real_food_webs.json`.
- Random game states generated by `train.py`.
- Perturbed real-food-web game states generated by `train.py`.
- Optional external sheet data if provided during training.

Default generated training mix:

| Source type | Approximate share |
|---|---:|
| Random game states | 10% |
| Real food-web based states | 60% |
| Perturbed real food-web states | 30% |

See `docs/DATA_CARD.md` for dataset details.

## 7. Training Procedure

Default training configuration from `train.py`:

| Setting | Value |
|---|---:|
| Synthetic sample count | 5,000 |
| Epochs | 40 |
| Batch size | 32 |
| Learning rate | 3e-4 |
| Optimizer | AdamW |
| Weight decay | 1e-4 |
| Scheduler | CosineAnnealingLR |
| Split | 90% train / 10% validation |
| Score loss | MSE |
| Recommendation loss | Binary cross entropy with logits |
| Combined loss | `score_loss + 0.3 * recommendation_loss` |
| Gradient clipping | 1.0 |

Species2Vec pretraining:

- Uses `species2vec.py`.
- Default embedding dimension: 16.
- Default pretraining epochs: 300.
- Output artifact: `species2vec.pt`.

## 8. Evaluation

The repository includes a local hold-out evaluation from `holdout_test.py`.

Current local hold-out summary from `holdout_report.txt`:

| Method | Hit@5 |
|---|---:|
| GNN | 92.0% |
| Rule / hybrid recommendation | 100.0% |
| Pure Jaccard baseline | 100.0% |
| Score-only baseline | 13.0% |

Interpretation:

- The GNN strongly outperforms the score-only baseline in the recorded hold-out test.
- The Jaccard and rule/hybrid baselines outperform the current GNN in this small test.
- The result suggests that the current GNN learns useful graph structure but does not yet surpass the strongest co-occurrence baseline.

Known evaluation limitations:

- The hold-out report uses 100 trials, which is useful for project validation but not enough for broad scientific claims.
- The evaluation focuses on recommendation Hit@5, not player satisfaction, ecological realism, latency, or robustness.
- No disaggregated evaluation by ecosystem type is currently documented.
- No adversarial or stress-test evaluation is currently documented.

## 9. Explainability

The GNN model itself is not directly interpretable to players because node embeddings, attention layers, and graph-level pooling compress the ecosystem into latent vectors.

EcoChain therefore uses a separate explainable scoring path for the displayed health score:

- Shannon diversity
- Trophic completeness
- Aquatic habitat bonus or penalty
- Pollinator bonus
- Facility bonus
- Random event and market item adjustments

This design separates two responsibilities:

| Component | Role |
|---|---|
| Explainable formula | Player-facing health score |
| GNN | Recommendation and graph analysis support |

## 10. Ethical and Safety Considerations

This model is used in a game and educational project, not in a real-world ecological management system.

Main risks:

- Users may overinterpret simplified ecological recommendations as scientific advice.
- The model may recommend species based on simplified co-occurrence rather than full ecological constraints.
- Small training data may cause recommendation bias toward known food-web subsets.
- Model predictions and recommendations may be unstable if species mappings or training data change.

Mitigations:

- Keep the displayed score explainable.
- Label GNN outputs as recommendation support rather than scientific truth.
- Maintain a Data Card and Model Card with every major retraining.
- Keep evaluation artifacts next to model artifacts.
- Avoid using user account data in model training unless a separate privacy review is completed.

## 11. Security and Deployment Notes

The backend exposes GNN analysis endpoints. Security controls should include:

- API input validation for species IDs and request shape.
- Rate limiting for GNN analysis routes.
- No secrets in model files or dataset files.
- Azure and Firebase credentials stored outside the repository.
- Model artifact updates reviewed before deployment.

## 12. Caveats and Recommendations

Recommended before future model releases:

1. Record the exact training command, random seed, and git commit.
2. Add a new hold-out report after retraining.
3. Compare GNN against Jaccard, rule/hybrid, and score-only baselines.
4. Add evaluation by ecosystem type: aquatic, terrestrial, predator-heavy, plant-heavy, facility-heavy.
5. Track model latency for local and Azure deployment.
6. Consider exposing recommendation reasons separately from the health score.
